## External Credentials

*The auth half of the modern Named Credential model.*

### 🌱 Simple

*Beginner - plain language*

**External Credentials** define the *authentication* for an outbound integration (protocol, flow, principals) — paired with a Named Credential that defines the *endpoint URL*.

### 📏 Limits

*Governor & platform limits*

- Principal access must be granted via permission set; profiles alone are insufficient.
- Secrets never deploy between orgs.
- Custom header formulas are evaluated on every callout.
- Some authentication protocols are unavailable on legacy Named Credentials.

## Principals

*The identities/secrets used by an External Credential.*

### 🌱 Simple

*Beginner - plain language*

**Principals** in an External Credential represent the identity and secret used to authenticate — e.g., a named principal (one shared identity) or per-user principals (each user's own credentials).

### 📏 Limits

*Governor & platform limits*

- Named Principal shares one identity org-wide; Per User Principal requires each user to authorise.
- Per User Principal adds a first-use authorisation step that must be designed into the UX.
- Missing principal access throws `CalloutException` before any network call.
- Principals are granted through permission sets only.

## Auth Providers

*Configured external identity providers for OAuth/OIDC.*

### 🌱 Simple

*Beginner - plain language*

**Auth Providers** configure external identity/OAuth providers (Google, Azure AD, Facebook, custom OIDC) so Salesforce can authenticate users against them or obtain tokens for callouts.

### 📏 Limits

*Governor & platform limits*

- Callback URL is generated by Salesforce and must be registered externally.
- The Registration Handler runs in system context - you own all validation.
- Token refresh depends on the provider issuing a refresh token, which many do not by default.
- JIT-created users consume licences.

## Secret Management

*Securely storing, scoping, and rotating integration secrets.*

### 🌱 Simple

*Beginner - plain language*

**Secret management** means keeping integration credentials (secrets, keys, tokens) out of code — stored encrypted in the platform (Named/External Credentials), access-controlled, and rotated.

### 📏 Limits

*Governor & platform limits*

- Secrets in Custom Settings or Custom Metadata are visible to anyone with Modify All Data.
- Named/External Credential secrets never deploy and are entered per org.
- Protected Custom Metadata is only protected inside a managed package.
- Secrets must never appear in Git, debug logs or error messages.
