## Lightning Experience

*The modern Salesforce UI — component-based, productive, the default for new work.*

### 🌱 Simple

*Beginner - plain language*

**Lightning Experience (LEX)** is the modern Salesforce user interface — clean, fast, and built from reusable components. It replaced the older "Classic" look and is where all new features land.

### 📏 Limits

*Governor & platform limits*

- Some Classic features have no Lightning equivalent and vice versa.
- Page load (EPT) is sensitive to layout weight and component count.
- Locker Service / Lightning Web Security restrict third-party JavaScript.
- Not all managed packages are Lightning-ready.

## Salesforce Classic

*The legacy UI — still around, but feature-frozen and being retired. Avoid for new work.*

### 🌱 Simple

*Beginner - plain language*

**Salesforce Classic** is the older user interface. It still works in some orgs but receives no new features and is gradually being retired. New projects should use Lightning Experience.

### 📏 Limits

*Governor & platform limits*

- No longer receives new features - it is maintenance-only.
- Lightning components and Dynamic Forms do not render in Classic.
- Visualforce built for Classic often needs rework for Lightning.

## App Launcher

*The grid menu (9 dots) to switch between apps and find any item/object quickly.*

### 🌱 Simple

*Beginner - plain language*

The **App Launcher** is the waffle icon (nine dots) at the top-left. Click it to switch between apps (Sales, Service, custom apps) and to search for any object, tab, or item you have access to.

### 📏 Limits

*Governor & platform limits*

- Shows only apps and items the user has visibility for via profile or permission set.
- Custom app counts are limited by edition.
- Ordering is per user and cannot be centrally enforced for all items.

## Utility Bar

*The persistent footer bar in Lightning apps for always-available tools (notes, history, softphone).*

### 🌱 Simple

*Beginner - plain language*

The **Utility Bar** is a fixed bar at the bottom of a Lightning app holding quick-access tools — like notes, recent items, a softphone (CTI), or a to-do list — available from any page in the app.

### 📏 Limits

*Governor & platform limits*

- Utility items are always loaded, so heavy components there slow every page in the app.
- Limited number of utility items per app before the bar becomes unusable.
- Not available on mobile.

## Console Navigation

*Tabbed, multi-record workspace for high-volume work (Service Console) — subtabs & split view.*

### 🌱 Simple

*Beginner - plain language*

**Console navigation** turns an app into a tabbed workspace: you open multiple records as tabs and subtabs at once, ideal for agents juggling many cases. It's the layout behind the Service Console.

### 📏 Limits

*Governor & platform limits*

- Open tabs accumulate memory and component state; the console degrades over a working day.
- Workspace API is available only in console apps.
- Not supported in the mobile app.

## Standard Navigation

*Single-page navigation (one record at a time) — the default for most sales/admin users.*

### 🌱 Simple

*Beginner - plain language*

**Standard navigation** is the normal Lightning layout: you view one record/page at a time, navigating via the top menu. It's simpler than the tabbed Console and fits most sales and admin users.

### 📏 Limits

*Governor & platform limits*

- Single-record focus - no subtabs, so multi-record workflows are slower.
- Workspace API is unavailable.
- Switching a live app between console and standard changes user muscle memory significantly.

## Global Search

*The top search box — SOSL-powered search across objects, ranked and access-filtered.*

### 🌱 Simple

*Beginner - plain language*

**Global Search** is the search box at the top of Salesforce. Type a name, number, or keyword and it searches across many objects at once, showing results you have permission to see.

### 📏 Limits

*Governor & platform limits*

- Relies on the search index, which updates asynchronously - very recent records may be missing.
- Only searchable field types are indexed; encrypted and some long-text fields are excluded.
- Results are capped and further filtered by sharing.
- Ranking is platform-controlled and cannot be tuned.

## Favorites

*Personal bookmarks (star icon) for quick access to records, lists, reports, dashboards.*

### 🌱 Simple

*Beginner - plain language*

**Favorites** let each user bookmark records, list views, reports or dashboards with the star icon, then jump back to them quickly from the favorites menu. It's personal — each user manages their own.

### 📏 Limits

*Governor & platform limits*

- Limited number of favourites per user (typically 200).
- Per user only - they cannot be provisioned or enforced centrally.
- Favourites to deleted records break silently.

## Split View

*List + record side-by-side — work a list without losing your place. Great in Console.*

### 🌱 Simple

*Beginner - plain language*

**Split View** shows a list of records on the left and the selected record on the right at the same time, so you can move through a list quickly without going back and forth.

### 📏 Limits

*Governor & platform limits*

- Available on list views for supported objects only.
- Still bounded by the 2,000-record list view display limit.
- Not available in the mobile app.

## Kanban View

*Drag-and-drop board grouped by a picklist (e.g., Opportunity Stage) — visual pipeline.*

### 🌱 Simple

*Beginner - plain language*

**Kanban view** displays records as cards in columns grouped by a status field — like Opportunity Stage. You drag a card from one column to the next to update its stage, giving a visual board of your pipeline.

### 📏 Limits

*Governor & platform limits*

- Limited to a set number of records per column (typically 200) and 20 columns.
- Only picklist fields can be used for grouping.
- Summary calculations are limited to a small set of aggregate field types.
