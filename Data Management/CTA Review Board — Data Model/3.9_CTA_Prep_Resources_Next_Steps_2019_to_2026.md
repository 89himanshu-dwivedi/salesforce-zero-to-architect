# 2. License Capability Matrix — Data Model Ka Sabse Bada Blind Spot

## Core Principle

> **Galat license = poora data model bekaar.**

CTA scenario mein aap ek perfect-looking data model bana sakte ho, lekin agar jis user ke liye design kiya hai uska license required object/capability support hi nahi karta, toh architecture fail ho sakta hai.

---

## 2.1 Real Mistake Jo Presenter Se Hui

Original scenario:

> **"Main chahti thi ki partner users products create kar sakein — par wo products create kar hi nahi sakte, sirf view kar sakte hain."**

### Lesson

Data model design se pehle ye verify karo:

```text
Requirement
    ↓
User Type
    ↓
License
    ↓
Object Access
    ↓
CRUD
    ↓
Feature / Permission
    ↓
Data Model
```

Agar license layer fail ho gayi:

```text
Wrong License
     ↓
Required Object Access Missing
     ↓
CRUD Requirement Fails
     ↓
Data Model / Architecture Fails
```

# 4. 2026 Update — License vs SKU vs Permission

Salesforce current documentation license ko capability/access ka important gateway maanta hai, lekin actual access sirf license name se decide nahi hota.

Evaluate:

```text
User License
      +
SKU / Purchased Product
      +
Profile
      +
Permission Sets
      +
Permission Set Licenses
      +
Object Permissions
      +
Feature Permissions
      +
Sharing
```

Salesforce specifically notes that SKU names and license names always map one-to-one nahi hote. For example, the Partner Community license can be sold through different SKUs with different platform-capacity characteristics. citeturn0search1

### Interview-Safe Statement

> **"I don't design from the license name alone. I validate the exact user license, SKU, object access, CRUD, permission-set licenses and feature entitlements required by the use case."**
