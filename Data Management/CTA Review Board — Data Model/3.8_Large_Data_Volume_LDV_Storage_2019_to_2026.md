# 2. Option 1 — Standard / Custom Objects

## Original Rule of Thumb

> **20 million tak.**

### Pehli Koshish Hamesha Yahi

Jahan tak possible ho, **standard ya custom objects** use karo — kyunki inke saath Salesforce ke normal platform features available hote hain.

### ⚡ Poora Automation

- Flow
- Process Builder
- Workflow

sab available ho sakte hain, depending on the feature and object.

### 🔒 Sharing Aur Security

- OWD
- Roles
- Sharing Rules
- Other standard Salesforce sharing mechanisms

available hote hain.

### 📄 Page Layouts Aur UI

Standard Salesforce UI capabilities available hoti hain.

### 📊 Reports Aur Dashboards

Normal reporting/dashboard capabilities available hoti hain.

## 2.1 20 Million Ke Aas-Paas Aane Par

Original scenario:

```text
Custom Object mein data badh raha hai

10M
 ↓
15M
 ↓
20M
```

### Volume Kitna Hai?

#### Success

**Comfortably Under 20M**

→ Sab theek

→ **Normal Object Use Karo**

→ Poora feature set

#### Failure

**20M ke kareeb — ya 10M par bhi heavy queries**

Possible symptoms:

- Queries timeout
- Reports slow
- Views / List Views slow

Possible performance actions:

- **Custom Indexes Salesforce se maango**
- **Skinny Tables consider karo**
- Sirf zaroori fields ki optimized table/query path use karo
- Agar normal object architecture still insufficient ho, alternative storage architecture consider karo

### Original Flow

```text
Normal Object
     ↓
Volume / Query Performance
     ↓
 ┌───────────────┬──────────────────┐
 ↓               ↓
Healthy          Heavy / Slow
 ↓               ↓
Continue         Optimize
                 ↓
          Index / Skinny Table
                 ↓
          Still insufficient?
                 ↓
          Alternative architecture
```
