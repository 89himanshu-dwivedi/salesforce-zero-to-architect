# 1.4.1 Validation Rules — Zaroori Hain, Par Zyada Hue To Adoption Marta Hai

Validation Rules Salesforce mein data quality enforce karne ka important mechanism hain.

> **Validation Rule = Record save hone se pehle business condition check karna.**

```text
User Enters Data
      ↓
Validation Rule
      ↓
Invalid?
 /      \
Yes      No
 ↓        ↓
Error    Save
 ↓
Fix Data
```

Salesforce validation rules new/updated records par apply ho sakte hain aur invalid data ko save hone se rok sakte hain.

## Source Session Ka Practical Lesson

Speaker ke consulting experience mein validation rules ka use baad mein **kam** hua, kyunki excessive validation user adoption ko hurt kar sakti hai.

### Failure

```text
Too Many Rules
    ↓
Frequent Errors
    ↓
User Frustration
    ↓
Admin Tickets
    ↓
Workarounds
    ↓
Adoption Down
```

### Success

```text
Critical Rule
    ↓
Clear Error
    ↓
User Understands
    ↓
Fixes Data
    ↓
Good Quality + Good UX
```

## Classic Admin Moment

User: **"Ye kaam nahi kar raha."**

Admin wahi validation error copy-paste kar deta hai.

User: **"Oh, mujhe pata nahi tha."**

### Lesson

Error message self-explanatory hona chahiye, lekin usse bhi pehle socho:

> **Kya ye validation rule sach mein necessary hai?**

Salesforce guidance recommends error messages that tell the user what kind of value is valid and identify the relevant field where useful.

### Good Error

❌ `Invalid data.`

✅ `Close Date must be today or a future date.`

✅ `Select Customer Type before setting Stage to Closed Won; this value is required for downstream billing.`

# 1.4.2 Validation Rules — Integration Gotcha

Validation rules ko sirf UI control mat samjho.

A validation rule ka impact relevant API/integration save operations par bhi ho sakta hai.

```text
Validation Rule
   ↓
UI
+
API
+
Integration
+
Automation
```

### Architect Question

> "Agar ye validation enable kiya, kya existing integration required values supply karti hai?"
