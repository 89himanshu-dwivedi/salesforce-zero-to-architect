# 1.9 Governance Strategy Ka 4-Step Plan

**Analyse → Plan → Implement → Sustain**

Jab project aage badh jaata hai aur business poochhne lagti hai ki **data clean kaise rakhenge**, tab ye 4-step approach kaam aata hai:

1. Current State Analysis
2. Develop The Plan
3. Implement
4. Sustain After Go-Live

> **Order important hai — analysis skip kiya to plan galat banega.**

---

# 1. Chaaron Steps Ek Nazar Mein

## Governance Implementation Ka Pipeline

```text
1 · Current State Analysis
        ↓
Kya chal raha hai?
Pain points kya hain?
        ↓
2 · Develop The Plan
        ↓
Data, standards, roles, metrics define karo
        ↓
3 · Implement
        ↓
Sandbox rehearsal → Production
        ↓
4 · Sustain After Go-Live
        ↓
Committees + Dashboards + Collaboration + Culture
```

| Step | Main Focus |
|---|---|
| **1. Current State Analysis** | Kya chal raha hai, pain points kya hain |
| **2. Develop The Plan** | Data, standards, roles, metrics define karo |
| **3. Implement** | Sandbox rehearsal, phir production |
| **4. Sustain After Go-Live** | Committees, dashboards, Chatter/collaboration, culture |

---

## Common Mistake

Log seedha Step 2 ya Step 3 par chale jaate hain:

> "Chalo validation rules daal dete hain."

Bina current-state analysis ke validation rules ya controls **galat jagah** lag sakte hain.

Correct sequence:

```text
Understand
   ↓
Plan
   ↓
Build
   ↓
Sustain
```

# 2. Step 1 — Current State Analysis

## Who, What, Why, How

Har cheez ka answer **kaun / kya / kyu / kaise** mein nikalo.

### 👤 Kaun Use Kar Raha Hai

Identify karo:

- Kaunse teams data use karte hain?
- Kaunse roles data ko touch karte hain?
- Kaun data create/change karta hai?

### ❓ Kyu Use Kar Rahe Hain

Data kis business purpose ke liye use ho raha hai?

Example:

```text
Customer Data
   ↓
Sales
Support
Marketing
Reporting
```

### 🔧 Kaise Use Ho Raha Hai

Data kis form mein use ho raha hai?

- Report
- Process
- Integration
- Operational activity

### 📊 Kaunsa Data Actually Use Hota Hai

Ye differentiate karo:

```text
Data Actually Used
        vs
Data Sirf Collect Kiya Ja Raha Hai
```

Har collected field automatically valuable nahi hoti.

### 🎯 Kaunse Decisions Drive Hote Hain

Identify karo:

> Kis data se kaunsa business decision banta hai?

Example:

```text
Customer Segment
     ↓
Marketing Decision
```

### 🗑️ Sirf Nice-To-Have To Nahi?

Question:

> Kya hum data sirf isliye collect kar rahe hain kyunki "achha lagega"?

Agar business value nahi hai, to collection/maintenance cost justify karni chahiye.

# 3. Quality Aur Consistency Ka Assessment

## Account Type Field Ka Classic Mess

Example:

```text
Field: Account Type
Type: Picklist
```

Kuch users ne:

```text
"Active Customer"
```

enter kiya.

Ab question:

> **Consistent values hain?**

---

## ✅ Success

```text
Ek Hi Standard
       ↓
Sabne Same Value Use Ki
       ↓
Reporting Saaf
       ↓
Numbers Par Bharosa
```

---

## ❌ Failure

Admin ne naya value bana diya:

```text
Account Type = "Customer"
Status       = "Active"
```

Ab same business concept do jagah represent ho raha hai.

```text
Do Tarike Ban Gaye
       ↓
Same Cheez, Do Jagah
       ↓
Reporting Confusion
       ↓
Counts Match Nahi Karte
```

### Normal / Success / Failure / Watch-out

| Situation | Success Path | Failure / Error Path | Watch-out |
|---|---|---|---|
| Picklist standard | One agreed value set | Users create different meanings | Business definition first |
| Account classification | One clear field/standard | Same concept split across fields | Avoid duplicate representation |
| Reporting | Consistent values | Counts don't match | Reporting logic depends on data standard |

# 4. Aur Ye Bhi Poochho

Data **kaun create/change** kar raha hai?

Possibilities:

- Automation
- Human
- Integration

Aur:

- Kya kuch teams hi data ko touch kar sakti hain?
- Kaun change kar sakta hai?
- Kaun monitor karta hai?
- Kaun responsible hai?

In sabka written **Current State Analysis** banta hai.

Uske baad hi Step 2 start hota hai.

# 5. Real Case Study — Consent Capture Ka Business vs IT Debate

> **Kabhi-kabhi sahi jawaab "Salesforce solution nahi" hota hai.**

Ek real workshop challenge mein client ko **basis of consent** track karna tha.

Do different requirements aayi.

---

## Business Ki Requirement

Business ko chahiye tha:

- Bas ye pata ho ki customer ne consent diya ya nahi
- Isse zyada kuch nahi chahiye
- Agent ko sirf `"customer happy hai"` type simple indication dikhna chahiye

---

## IT Ki Requirement — Fair Point

IT ki requirement detailed thi:

- Ek customer ke against **multiple consent records**
- Personal data aur sensitive data alag-alag track ho
- Compliance reporting ke liye required detail maintain ho

Dono requirements apne context mein valid ho sakti hain.

---

# 6. Consent Ko Kahan Build Karein?

## Step 1 — Dono Requirements Valid Hain

```text
Business
→ Simple experience

IT
→ Detailed consent model
```

---

## Step 2 — Existing Landscape Dekho

Check karo:

> IT ke paas already kaunse systems hain?

Agar existing systems already consent analyse aur report kar rahe hain, to Salesforce mein duplicate solution build karna zaroori nahi ho sakta.
