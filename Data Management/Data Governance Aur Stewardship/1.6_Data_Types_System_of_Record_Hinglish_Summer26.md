# 1.6 Data Ke 4 Types Aur System of Record Ka Faisla

**Master, Transactional, Reference aur Metadata**

Governance conversation ke liye pehle ye samajhna padta hai ki aapke system mein kaunsa data hai.

Chaar main buckets:

1. Master
2. Transactional
3. Reference
4. Metadata

Har bucket ka **System of Record (SOR)** alag ho sakta hai.

---

## 1. Master, Transactional, Reference Aur Metadata — Chaaron Ka Farak

Ye concept **exam mein aur client conversation mein dono jagah** kaam aata hai.

### 🌟 Master Data

Customer aur prospect data.

Organisation mein iska ek System of Record hota hai — **often Salesforce, par hamesha nahi**.

Example:

```text
Customer
Prospect
Account
Contact
```

Governance questions:

- SOR kaun hai?
- Kaun update kar sakta hai?
- Data ka owner kaun hai?
- Dusre systems ko ye data kahan se milega?

---

### 💳 Transactional Data

Business transactions ko represent karta hai.

Examples:

- Orders
- Contracts
- Payment information
- Invoices

Governance questions:

- Kis system se aata hai?
- Kaunsa system transaction ka authoritative source hai?
- Kitna retain karna hai?
- Kis system mein transaction create/update hoga?

---

### 📏 Reference Data

Reference data wo controlled values hain jinka use business meaning aur classification ke liye hota hai.

Examples:

- Currencies
- Exchange rates
- Codes
- Classification values

Example:

```text
Customer Status

Active
Inactive
```

Governance question:

> Business mein "Active" aur "Inactive" ka exact meaning kya hai?

Reference data ke liye important hai ki values ka business definition clear ho aur maintenance ownership defined ho.

---

### 📈 Metadata

Script ke context mein metadata examples:

- Record kitni baar view hua
- Kitni activities log hui

Is information ka use adoption aur quality ko measure karne ke liye kiya ja sakta hai.

Example:

```text
Record Views      → 250
Activities Logged → 18
```

Isse organization samajh sakti hai ki data/system actually use ho raha hai ya nahi.

---

## 2. Four Data Types — Quick Table

| **Type** | **Example** | **Governance Sawaal** |
| :--- | :--- | :--- |
| **Master** | Customer, prospect | SOR kaun hai? Kaun update kar sakta hai? |
| **Transactional** | Order, contract, invoice, payment | Kis system se aata hai? Kitna retain karna hai? |
| **Reference** | Currency, exchange rate, classification codes | Kaun maintain karta hai? Business definition kya hai? |
| **Metadata** | View count, activity count | Adoption measure karne ke liye kaise use karein? |

# 3. System Of Record Kaun — Salesforce Hamesha Nahi Hota

**Salesforce automatically har type ke data ka SOR nahi hota.**

Ek bespoke / home-made system bhi master ho sakta hai.

Aam taur par Salesforce customer aur prospect data ka main SOR ho sakta hai.

Lekin:

- Transactional systems master ho sakte hain.
- ERP system master ho sakta hai.
- Bespoke system master ho sakta hai.
- Regulatory/policy data kisi external system mein master ho sakta hai.

Isliye SOR ka decision **data type/domain ke basis par** hona chahiye, sirf platform ke naam ke basis par nahi.

# 4. Real Project Example — Hierarchical SOR Setup

### Bespoke Home-Made System

```text
Bespoke Home-Made System
        ↓
Sab kuch isme hai
        ↓
Asli Master
```

### Doosre Systems Ko Feed

```text
Bespoke System
       ↓
 ┌─────┼─────┐
 ↓     ↓     ↓
Salesforce  Other Systems
```

Yaani bespoke system se doosre systems ko data feed hota hai.

### Salesforce

Salesforce **contact centre users ka interaction point** ho sakta hai.

Is example mein:

```text
Policy Data
     ↓
Bespoke System = SOR

Customer Interaction / Activity
     ↓
Salesforce = SOR
```

Isliye same ecosystem mein different data ke liye different SOR ho sakte hain.
