## 2.9 Lock Contention Ko Kam Karne Ki Strategies

### Source Script Ka Core Idea

Lock contention ko poori tarah rokne ke kai practical tareeke hain:

- Lookup configuration tweak
- Parent ID se sorting
- Sahi chunking
- Validation Rules / Triggers / Workflows disable ya defer karna
- Roll-Up Summary ki jagah summary reporting
- Sharing calculations defer karna

### Simple Mental Model

```text
Lock Contention Reduce Karna

        |
```

# Strategy 1 — Lookup Ka Delete Behaviour Config Tweak Karo

## Ek checkbox jo parent lock rok sakta hai

Lookup relationship definition me ek configuration hoti hai jo decide karti hai ki lookup record delete hone par kya behavior hoga.

Source script ka important point:

> Agar optional lookup field ke liye **“Clear the value of this field”** behavior configure kiya jata hai, to Salesforce lookup value ko protect karne ke liye unnecessary lookup-record locking ko avoid kar sakta hai.

Iska practical benefit large data loads me lock contention reduce karna hai.

### Salesforce Lookup Delete Behaviour

Optional lookup relationship me Salesforce commonly ye behaviors provide karta hai:

1. **Clear the value of this field**
2. **Don’t allow deletion of the lookup record that’s part of a lookup relationship**
3. **Delete this record also** — availability relationship/object context par depend karti hai

Salesforce Help ke according, **“Clear the value of this field” default behavior hai** for an optional lookup. Current Salesforce documentation bhi relationship delete behavior ko isi tarah describe karti hai.

> **Important:** Source script ka performance/locking point specifically optional lookup ke **“Clear the value of this field”** behavior se related hai. Isko blindly har lookup par apply nahi karna chahiye.

## Ye Checkbox Uncheck Karein Ya Nahi

| Condition | Decision | Result |
|---|---|---|
| Lookup Relationship Hai | Check karo | Parent-child relationship exist karti hai |
| Parent-child data load | Check karo | Bulk load me locks matter kar sakte hain |
| Lock Contention Expected Hai | Check karo | Lookup parent locking performance ko affect kar sakti hai |
| Bade volumes | Check karo | LDV me impact significant ho sakta hai |
| Kya Data Integrity Requirement Allow Karti Hai? | Decision point | Integrity requirement sabse pehle |
| **Success** | **Haan — Allow Karti Hai** | Parent delete par child ka strict protection rule required nahi |
| Checkbox Uncheck Karo / “Clear the value…” use karo | Configuration change | Relevant lookup locking reduce ho sakti hai |
| Parent lock nahi hoga | Expected benefit | Lock Contention Kam |
| Lock Contention Kam | Result | Load faster ho sakta hai |
| **Failure** | **Nahi — Integrity Zaroori Hai** | Parent ko protect karna required hai |
| Checkbox On Hi Rakho | Configuration unchanged | Data integrity pehle |
| Doosri Strategies Use Karo | Alternative | Sorting, chunking, automation control |
| Normal step |  | Configuration decision |
| Success path |  | Integrity permits change → locking reduce |
| Failure / error path |  | Integrity permits nahi karti → alternate strategies |
| Watch-out |  | Data integrity ke against configuration change mat karo |
