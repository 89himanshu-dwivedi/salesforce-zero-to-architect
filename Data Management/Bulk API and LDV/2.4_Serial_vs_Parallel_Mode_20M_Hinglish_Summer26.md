## 2.4 Serial vs Parallel Mode — Farak Aur Kab Kaunsa

Bulk API do modes me chalta hai:

- **Serial Mode**
- **Parallel Mode**

Basic difference:

- **Serial:** ek batch khatam hone ke baad hi agla batch process hota hai.
- **Parallel:** multiple batches ek saath process ho sakte hain.

### Core idea

**Serial = controlled processing / lower concurrency**

**Parallel = higher throughput / faster processing**

LDV (Large Data Volume) loads ke liye generally **Parallel Mode preferred** hota hai, lekin kuch important exceptions hain jahan locking ki wajah se **Serial Mode** better/sahi choice ban sakta hai.

Salesforce ke current documentation ke according Parallel mode default hai aur throughput improve kar sakta hai, lekin parallel processing record-lock contention create kar sakti hai. Serial mode batches ko one-at-a-time process karta hai aur lock contention ka chance reduce karta hai, at the cost of processing time. citeturn0search0turn0search1

## 20 Million Records Ka Case

Maan lo Salesforce me:

> **20 million records load karne hain.**

Ab dekhte hain Serial aur Parallel ka behaviour.

---

## Serial Mode

### Behaviour

- Ek batch khatam → tabhi agla batch uthta hai
- Sequence me chalta hai
- Ek time par effectively **one batch**
- 20 million records = **maan lo 1 ghanta**
- LDV ke liye **recommended nahi**
- Degree of parallelism **maximum 1**

### Visual Flow

```text
20 Million Records
        ↓
     Batch 1
        ↓
   Complete
        ↓
     Batch 2
        ↓
   Complete
        ↓
     Batch 3
        ↓
   Complete
        ↓
      ...
```

Yaani:

```text
Batch 1 → Batch 2 → Batch 3 → Batch 4 → ...
```
