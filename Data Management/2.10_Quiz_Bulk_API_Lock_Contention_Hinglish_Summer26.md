# Q3 — 60,000 Users Aur Role Hierarchy Wala Scenario

## Yahan Parallel Galat Jawaab Hai

### Question

LBA Corp ko **60,000 users** ka detail load aur update karna hai. Har user ek **well-defined role hierarchy** me hai.

Is integration ke liye aap kya recommend karenge?

---

# Sahi Jawaab — Bulk API Serial Mode

```text
60,000 Users
      |
      v
Role Hierarchy
      |
      v
Group Membership Lock Risk
      |
      v
Bulk API
      |
      v
Serial Mode
```

### Reasoning

- Org-wide **group membership table lock** lagta hai.
- Parallel mode me bahut saare locking errors aa sakte hain.
- Ye us exception case me aata hai jahan parallel achha perform nahi karta.
- Serial mode me ek batch ke complete hone ke baad next batch process hota hai.
- Isse group-membership-related lock contention minimize hota hai.

---

# SOAP API — “Kaam Kar Sakta Hai” Par Optimal Nahi

Source ka important distinction:

- Chhote volumes ke liye SOAP API chal jaata hai.
- 60,000 ke liye bhi shayad kaam kar sakta hai.
- Par bade volumes ke batch ke liye **optimal nahi**.
- Volume aur badha to fail hoga / performance unsuitable ho sakti hai.

### Exam Thinking

Question agar pooch raha hai:

> **“60,000 users + role hierarchy + Bulk API”**

to answer:

> **Bulk API — Serial Mode**

SOAP ko sirf isliye choose nahi karna hai ki woh technically records process kar sakta hai.

### Success Path

```text

    |
    v

    |

```

### Failure / Error Path

```text
Parallel Mode
    |
    v
Multiple batches simultaneously
    |
    v
Org-wide group membership lock competition
    |
    v
Locking errors
    |
    v
Load failure / retries
```

### Watch-out

Serial mode ka trade-off:

> **Reliable but slower**

Parallel mode normally faster hota hai, lekin group-membership lock scenarios ek important exception hain.
